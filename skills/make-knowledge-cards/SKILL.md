# Make Knowledge Cards — 知识卡片生成器

把一段文章（用户粘贴的文本）或本地 Markdown/TXT 文件，转换成 5~8 张结构化知识卡片。
每张卡片只讲一个知识点，包含四个字段：标题、核心知识、简明解释、例子或自测问题。

## 何时使用（When to use）

- 用户粘贴一段文章/文本，要求做成「知识卡片 / 学习卡片 / 卡片笔记 / 抽卡 / 复习卡片」。
- 用户给出本地 `.md` / `.markdown` / `.txt` 文件（路径或附件），要求转成卡片。
- 用户要求「把这段内容提炼成几张卡片」「整理成便于记忆的卡片」等同一意图。

## 何时不使用（When NOT to use）

遇到以下情况直接说明不支持，并给出替代建议，不要勉强产出：

- 输入是一个 URL（需要网页抓取）→ 请用户先把正文文本粘贴进来。
- 输入是 PDF / 扫描件 / 图片（需要文字提取）→ 请用户提供 Markdown/TXT，或直接粘贴文本。
- 用户要导出 Anki（`.apkg` / Anki 专用 CSV）或要求图形界面/网页应用 → 不支持。

## 输入处理（Input handling）

1. **粘贴文本**：直接使用用户消息中的正文，不额外联网、不引外部知识补充。
2. **本地文件**：仅支持 `.md` / `.markdown` / `.txt`。用 Read 工具读取全文；相对路径基于当前工作目录解析。文件不存在或不可读时如实告知，**不得臆造内容**。
3. 输入含混合内容（网页链接、图片、附件等）时，只使用其中可获取的纯文本；缺失部分如实说明。
4. 输入过短、信息量不足时，按实际内容产出（可少于 5 张），并简要说明原因。

## 工作流（Workflow）

### 第 1 步：通读并识别知识点
通读全文，列出候选知识点：定义、原理、因果关系、关键结论、步骤方法、易错点、概念对比、关键事实/数字。优先保留能独立成卡的「原子知识单元」。
判断「重要」时可参考：该点是否反复出现、是否是理解全文的关键、是否属于容易被误解之处。

### 第 2 步：去重与合并
语义重复或高度重叠的候选点合并为一条；互为补充的细节归入同一张卡；删除纯铺垫、口号性和与主题无关的枝节。同一知识点只保留一处。
不要机械地把原文的每个标题/小节都变成一张卡；小节标题不等于知识点，应按实际知识含量取舍。

### 第 3 步：确定卡片数量（5~8，可更少）
- 目标区间为 5~8 张，按重要性排序，优先保留核心。
- **信息不足时不强行凑数**：若全文真正重要的知识点不足 5 个，就输出实际数量（例如 3 张），并说明「原文可提炼的核心知识点有限」。
- 若知识点远超 8 个，只保留最重要的 5~8 个（或将相关点合并归类），不要机械罗列。

### 第 4 步：生成卡片
每张卡片严格套用下方「卡片格式」。输出语言与原文一致（中文原文用中文）。

### 第 5 步：自检（必须执行）
生成后逐条核对，不通过则修正后再输出：

- [ ] 每张卡只有一个知识点。
- [ ] 每张卡都包含四个字段，字段名一致。
- [ ] 「简明解释」在「核心知识」基础上补充了细节，而不是简单复述同一句话。
- [ ] 所有内容都能在原文中找到依据（**不编造**）：无依据的数据、结论、术语、引用一律不写。
- [ ] 没有重复卡片。
- [ ] 卡片数量在 5~8 之间，或已说明为何更少。
- [ ] 例子/自测问题确实针对该卡片的知识点，且答案能从原文推出。

## 卡片格式（Card format）

```
### 卡片 N：<标题>
- **核心知识**：<一句话点明这张卡要记住的核心结论或概念>
- **简明解释**：<2~4 句，把这个知识点讲清楚，基于原文表述>
- **例子 / 自测问题**：<原文有例子则用原文例子；否则依据原文信息提一个可自测的问题>
```

- **标题**：概括该知识点的短语（不要照抄原文标题，除非原文标题本身即该知识点）。
- **核心知识**：最凝练的一句，去掉修饰词。
- **简明解释**：通俗、准确、无冗余，并在核心知识之外补充细节，不要只是把核心知识换句话再说一遍。
- **例子 / 自测问题**：优先使用原文已有的例子；原文没有时，提出一个能检验是否理解的问题，答案必须能从原文推出。

### 参考示例
输入片段（节选自某篇关于缓存的文章）：「no-cache 比较容易被误解：它并不表示“不缓存”，而是表示“每次使用前必须向源服务器验证”。」

输出：

```
### 卡片：no-cache 不等于“不缓存”
- **核心知识**：no-cache 表示“每次使用前必须向源服务器验证”，而不是禁止缓存。
- **简明解释**：no-cache 容易被误解为不缓存；实际上它允许缓存，只要求每次使用前先验证。真正表示“任何位置都不得缓存”的指令是 no-store。
- **例子 / 自测问题**：想禁止任何位置缓存该响应，应使用哪个指令？（no-store）
```

## 输出规范（Output rules）

- 直接输出卡片，不复述原文，不加「以下是……」之类的套话（用户明确要求时可加）。
- 默认以 Markdown 输出；用户要求写入文件时写入 `.md`（除非用户指定路径）。
- 保持中性、准确，不添加原文没有的观点、评价或数据。
- 若用户指定了卡片数量，尽量满足；当指定数量超出原文可支撑范围时，先说明再按实际数量输出。

## 质量红线（Non-negotiables）

1. **不编造**：任何无法从原文得到的信息（数字、定义、结论、例子、引用）都不得出现。
2. **一卡一点**：不要把多个知识点塞进同一张卡。
3. **去重**：同一知识点只出现一次。
4. **宁少勿滥**：信息不足时如实减少数量，不用空话、常识或泛泛之谈填充。

## 不支持的能力（Out of scope）

- 网页抓取（从 URL 抓取正文）
- PDF / 扫描件 / 图片的文字提取
- Anki / `.apkg` / Anki 专用 CSV 导出
- 图形界面（GUI / 网页应用）
