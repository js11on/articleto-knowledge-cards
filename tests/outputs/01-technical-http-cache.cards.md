### 卡片 1：HTTP 缓存的核心思想是复用响应副本
- **核心知识**：HTTP 缓存通过在客户端或中间节点保存响应副本并复用，来减少重复请求、加快页面加载。
- **简明解释**：第一次请求得到的响应可以保存一份副本；当副本仍然“新鲜”时直接复用，不必再向源服务器发请求。它是浏览器、代理服务器和 CDN 共同使用的一套机制。
- **例子 / 自测问题**：当缓存副本仍然“新鲜”时，浏览器还需要向源服务器发请求吗？（不需要，直接复用本地副本）

### 卡片 2：Cache-Control 是控制缓存的关键响应头
- **核心知识**：Cache-Control 由多个指令组成，决定响应能否缓存、缓存多久、谁能缓存。
- **简明解释**：常用指令有 max-age、no-cache、no-store、public、private。max-age 指定响应在多少秒内被视为新鲜，如 max-age=3600 表示一小时；no-store 表示任何位置都不得缓存该响应；private 表示响应只能被浏览器等私有缓存保存，不能被 CDN 这类共享缓存保存。
- **例子 / 自测问题**：max-age=3600 表示响应在多少秒内被视为新鲜？（3600 秒，即一小时）

### 卡片 3：no-cache 不等于“不缓存”
- **核心知识**：no-cache 表示“每次使用前必须向源服务器验证”，而不是禁止缓存。
- **简明解释**：no-cache 容易被误解为不缓存；实际上它允许缓存，只要求每次使用前先验证。真正表示“任何位置都不得缓存”的指令是 no-store。
- **例子 / 自测问题**：想禁止任何位置缓存该响应，应使用哪个指令？（no-store）

### 卡片 4：缓存过期后靠 ETag / Last-Modified 做验证
- **核心知识**：缓存过期后通过 ETag 和 Last-Modified 验证，资源未变化则返回 304 并复用本地副本。
- **简明解释**：ETag 是资源版本标识符，Last-Modified 是资源最后修改时间。后续请求通过 If-None-Match（携带 ETag）或 If-Modified-Since（携带时间）把版本信息发给服务器；若资源没变化，服务器返回 304 Not Modified、响应体为空，浏览器直接使用本地副本以节省带宽；若资源变了，则返回 200 及完整新内容和新的 ETag。
- **例子 / 自测问题**：资源未变化时服务器返回哪个状态码，响应体是什么？（304 Not Modified，响应体为空）

### 卡片 5：强缓存与协商缓存的区别
- **核心知识**：强缓存在有效期内不与服务器通信，协商缓存每次都要向服务器发验证请求。
- **简明解释**：强缓存（fresh）在有效期内直接使用本地副本、不与服务器通信；协商缓存（stale）每次都要发验证请求。二者是同一套 Cache-Control/ETag 机制在不同阶段的表现，而不是互相独立的两套系统。
- **例子 / 自测问题**：强缓存和协商缓存是两套独立机制吗？（不是，是同一套机制在不同阶段的表现）

### 卡片 6：max-age 时长应按资源类型设置
- **核心知识**：max-age 并非越长越好，应根据资源类型（是否带哈希指纹）设置。
- **简明解释**：设得太长，用户可能长时间看到旧内容；设得太短，又会在验证上花费额外往返。带哈希指纹的静态资源（如 app.3f2a1b.js）可以设置很长的 max-age，因为内容变化时文件名也变；不带指纹的 HTML 通常使用较短的 max-age 或 no-cache，以便及时更新。
- **例子 / 自测问题**：为什么带哈希指纹的静态资源可以设置很长的 max-age？（因为内容变化时文件名也变，用户不会读到旧内容）
